# v0.3.0 – Semantic Memory

This release adds a durable SQLite store, vector-based memory ranking,
and memory expiry and archival controls.

The API now uses `memories.sqlite` by default. On first startup, it
validates and transactionally imports a legacy `memories.json`, then
preserves that file unchanged as a recovery snapshot. SQLite stores
float32 vectors beside the memories and invalidates a vector when its
memory text or category changes. Vectors are also tied to the configured
embedding endpoint and model, so changing providers triggers re-indexing.

Semantic ranking is optional. Configure an Ollama or OpenAI-compatible
embedding endpoint to enable it; otherwise, local lexical search remains
available. When enabled, the endpoint receives search queries and saved
memory text to create the local index. The settings page names this data
flow. Chat still receives only the selected active memories, bounded chat
history, and the current message.

Memories can be given an expiry date, archived, and restored. The default
memory list and chat retrieval exclude archived and expired records, and
separate views keep those records available until they are deleted.

Local development requires Node.js 22.13 or newer. Docker Compose
continues to provide its own runtime. See
[deployment and recovery](deployment.md) for configuration, migration,
privacy, and backup instructions.

Validation for this release includes lint, type checking, unit tests,
API integration tests, UI tests, BDD scenarios, and production builds.
