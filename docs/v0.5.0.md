# v0.5.0 – Automation

Home Memory Agent can now run persistent tasks on a recurring interval or when
a memory is created or updated. The Automations page supports task creation,
pause/resume, manual runs, recent run history, and in-app notifications.

The API stores automation definitions, queue state, retry attempts, results,
and notification read state in `data/automations.sqlite`. Scheduled occurrences
and memory events use idempotency keys. A failed task is retried up to three
times with bounded backoff; interrupted work is recovered after a process
restart. Results and terminal failures create one local notification per run.

Automations use the configured model and may use only the read-only tools
enabled in `AGENT_TOOLS`. They can read up to five relevant active memories but
cannot create, update, archive, or delete them. As with chat, task prompts,
selected memories, and tool results may be sent to the configured provider or
to an explicitly enabled external tool service. Review the Settings page before
creating tasks that include private information.

The scheduler runs inside the API process and checks for due work every five
seconds. Keep the service running for scheduled tasks to start. Back up both
`memories.sqlite` and `automations.sqlite` from the data directory. The
automation database is used even when `MEMORY_STORE=json` is selected.

Intervals can be set from 15 minutes through 7 days. If the service was down
for several intervals, it queues the latest due occurrence and advances to the
next future interval instead of replaying every missed occurrence.
