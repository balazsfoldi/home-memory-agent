# v0.4.0 – Agent Tools

The assistant can now request three bounded, read-only operations: a
weather forecast, local calendar lookup, and saved-memory search. The
server keeps an explicit per-operation allowlist in `AGENT_TOOLS`, validates
tool input, limits each chat request to three executions, and reports which
tools were used. Disabled operations never execute, even when a model asks
for them. Tool output is treated as untrusted data.

Weather forecasts use Open-Meteo. The requested place name is sent to that
external service, and Settings discloses the transfer. Calendar lookup
reads `data/calendar.ics` from the local data directory. It supports
single events and preserves time-zone fields; recurring rules are reported
but are not expanded. Memory lookup remains local unless semantic
embeddings are configured, in which case the existing embedding data-flow
notice applies.

All three tools are disabled by default. Enable selected operations in the
server `.env` file and restart the service. See [deployment and recovery](deployment.md)
for configuration and calendar setup.

Validation covers tool permission enforcement, input and result bounds,
forecast parsing, local calendar parsing, chat orchestration, the UI, and
the full existing API, BDD, and production-build checks.
